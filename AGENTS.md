# Comparison site instructions

- Comparison pages created or updated in this workspace are intended for other people to open as public webpages. Publish them through this repository's GitHub Pages; a local preview alone is not a completed delivery.
- Include the page's required manifests and video assets in the published site, then verify the public URL and media load after deployment.
- The user has explicitly authorized public access for comparison pages in this workspace. Do not ask for that authorization again for each comparison page.
- Every comparison page must explain what each side contains, where the source videos came from, and any material differences such as resolution, duration, or processing method. Show each video's actual resolution when paired dimensions differ, and link the upstream model/code when the compared output uses an open-source method.
- Upload every comparison video's original MP4 to the configured Cloudflare R2 bucket using the repository publisher. Keep source videos unmodified, verify uploaded object sizes, and check public media URLs after deployment. Do not leave comparison video assets hosted only in the GitHub repository.
- Paired playback must wait until both clips have playable data before starting. If either clip buffers or stalls, pause both at the same point, show a buffering message, and resume them together when both can continue.
- For pages comparing model-generated results, include a concise run summary with the relevant inference settings, per-video runtime (prefer mean, median, and range across the compared set), process-level peak GPU memory, and total model-weight size; add the useful weight breakdown when available. State what each runtime figure includes, distinguish model inference from end-to-end per-video processing when both are available, and clarify whether GPU memory is a per-device value or a process total across devices. If a metric was not captured, label it “未记录” instead of estimating it. For non-model comparisons, include only applicable processing details.
- Public pages must not expose private server details: omit filesystem paths, internal hostnames/IPs, usernames, process IDs, local log locations, credentials, and other operational details. Do not publish raw prompts or other sensitive inputs; summarize only relevant reproducibility settings. Keep the public run summary focused on information useful for understanding the comparison.
